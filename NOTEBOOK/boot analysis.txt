  ---
  Biggest Architectural Difference: Per-Button 7-Segment Price Displays

  The old machine had simple LED buttons (4F/4B for on/off). This machine sends the actual price digits to each button address using the same 7-segment inverted encoding as the HEAD display:

  VM ROOT → 08:83  C0 [tens_byte] [hund_byte] FF FF FF FF FF FF FF FF FF FF FF FF

  C0 = display active, then price digits little-endian, then FF (blank) padding. The E2 00 00 follow-up is sent after each price write (not present in old machine — likely commits the display update).

  OOS state = C0 BF BF BF BF FF... where BF XOR FF = 40 = only the middle segment on → shows "----" (four dashes). This is the "digital display that blanked when OOS" you described. Unlike the old machine's
   simple LED toggle, this machine's buttons visually show the price or dash-out.

  Both LED state (4F/4B) and 7-segment price commands are used together — the price display updates happen per-transaction while LED sweeps happen on a timer.

  ---
  Confirmed Dispense (t=00:02:55)

  Button 9 (08:88) pressed (90 press, 98 release). Dispense fired:
  35 00 00 33 45 05 10   ← slot 08 (mlo=33, mhi=45, speed=05, board=10)
  Same 35 command format as old machine. No 38 12 arm seen immediately before this (the 38 10 / 39 40 at boot may serve that role globally).

  New commands not in old machine:
  - E5 03 01 to HEAD → beep (fired just before dispense)
  - E2 00 00 → button display commit
